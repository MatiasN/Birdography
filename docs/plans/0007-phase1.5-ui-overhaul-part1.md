# Plan 0007: Phase 1.5 UI overhaul, Part 1 (designs, foundation, shell)

Status: decisions confirmed (2026-11-16), not started · Roadmap: [Phase 1.5](../../ROADMAP.md#phase-15-ui-overhaul) · Date: 2026-11-16

Phase 1.5 is split in two parts of about the same size. Part 1 settles how the app looks and how you move around
it: every page designed, the shared style and components, and the navigation with all five tabs. Part 2 then
builds the pages that need new features (Catalogue, Upload, empty states) and the README. Part 2 gets its own plan
(0008) once Part 1 is merged, because it depends on the mockups agreed here.

## 1. The split

| Roadmap item | Part 1 (this plan) | Part 2 (plan 0008) |
|---|---|---|
| Page designs | **All** mockups, both sizes, agreed before any page is built | Built from them |
| Design foundation | shadcn/ui set up, tokens, light/dark themes, typeface, icons, logo, the components Part 1 uses | Adds the components it needs |
| Adaptive layout | Sidebar / bottom bar, the five tabs, routes, profile page, placeholders for Species and Near me | — |
| Photo detail | New style: side panel on wide screens, full-screen sheet on phones, state in the URL | Species shown and editable in it |
| Map tab | New style (markers, group panel, detail sheet) | — |
| Upload tab | A placeholder pointing to the Catalogue's upload button (D8) | Uploading moves here: drag and drop, photo picker, progress per file, species while uploading |
| Catalogue tab | Current grid restyled; the upload button stays here, restyled, same behaviour | Filters (species, date, camera), paging past 50, room for Phase 2 grouping; the upload button leaves |
| Empty states | The `EmptyState` component, the two placeholder tabs | A real empty state on every tab for a new account |
| README | — | Logo, badges, screenshots, feature tour, quick start |

Part 1 has more design work and less feature work. Part 2 is the other way around. Each part ends with the
app working and CI green.

## 2. Current state

- `Layout.tsx`: a top header with *Photos*, *Map*, the email (links to `/account`) and *Log out*. No phone layout:
  the email is hidden below `sm` and that's all.
- Routes: `/` (Photos), `/map`, `/account`, `/login`.
- Styling: Tailwind 4 with no theme (`index.css` is just `@import "tailwindcss"`). Colours are written inline
  (`emerald-700`, `stone-*`) in every component. No dark mode, no shared components, no icons, no logo or favicon.
- `Photos.tsx` holds both the upload button and the grid. **The grid has no filters** and shows only the first 50
  photos: it calls `GET /photos` without `limit`/`offset`. The roadmap's ticked "Photo catalog UI with filters" is
  true only for the API (`PhotoFilters`). Part 2 fixes it (D10).
- No species UI anywhere. The API has search across the three names (`GET /species?q=`), create (`POST /species`)
  and assignment (`PATCH /photos/{id}` with `species_ids`). The dev seeder creates no species.
- `PhotoDetail` and `GroupPanel` are centred overlays with a backdrop button and `<dialog open>` (non-modal),
  closed with Escape.
- Tests: Vitest + jsdom, 104 tests, 100% coverage gate. Leaflet is replaced by `src/test/leaflet.tsx`.

## 4. Design foundation

**shadcn/ui (D6).** Set up with its CLI for Tailwind 4 (`npx shadcn@latest init`): `components.json`, the `@/`
import alias in `tsconfig.json` and `vite.config.ts`, `src/lib/utils.ts` (`cn()` with `clsx` and
`tailwind-merge`), and the `class-variance-authority`, `tw-animate-css` and Radix dependencies the components
bring. Components are copied into `src/components/ui/` and become our code: we edit them freely, they go through
Prettier, oxlint and the coverage gate like everything else, and only the ones in use are added
(`npx shadcn add <name>`), not the whole catalogue.

**Tokens.** shadcn's CSS variables in `index.css`, mapped to utilities with `@theme inline` as its Tailwind 4 setup
does. We keep its names, so components added later work without edits, and set the values for Birdography:

| Variable | Use |
|---|---|
| `background`, `foreground` | page, body text |
| `card`, `popover` (+ `-foreground`) | cards and panels, menus and sheets |
| `muted`, `muted-foreground` | secondary surfaces and text |
| `primary`, `primary-foreground` | primary actions, active tab, map groups (a green that works in both themes) |
| `secondary`, `accent` (+ `-foreground`) | secondary buttons, hover states |
| `destructive`, plus our own `warning` and `success` | errors, "No position", confirmations |
| `border`, `input`, `ring` | borders, inputs, focus rings |
| `sidebar-*` | the sidebar (§5) |
| `--radius` | one base radius, from which shadcn derives `sm`/`md`/`lg` |

The dark theme overrides the same variables under `.dark` on `<html>` (shadcn's convention), so components need
almost no `dark:` classes.

**Theme choice (D3).** *System* (follows `prefers-color-scheme`), *Light* or *Dark*, picked on the profile page and
stored in `localStorage`. A small blocking script, `public/theme.js` loaded in `<head>`, sets the `dark` class
before the first paint, so the page doesn't flash white in dark mode. It's an external file rather than inline, so a
future CSP (plan 0004 §12) doesn't need a hash for it. The `theme.ts` module (read, store, apply, follow system
changes) is unit-tested. (`next-themes`, which shadcn's docs suggest, targets Next.js; a 40-line module does the
same here.)

**Typeface (D4).** Inter variable, self-hosted through `@fontsource-variable/inter` (OFL), Latin and Latin-Ext
subsets (Portuguese names). Self-hosted means no request to a font CDN, and it keeps working offline once Phase 4
adds the PWA. Numbers in tables and counts use tabular figures.

**Icons (D5).** `lucide-react` (ISC), shadcn's default icon set, imported per icon so only the ones used get bundled.

**Logo.** A simple SVG mark plus the "Birdography" wordmark, drawn during the mockup step. It's also the favicon
(`favicon.svg` plus a 180 px PNG for iOS home screens). Part 2's README reuses it.

**Components (D6).** From shadcn, in `src/components/ui/`, plus a few of our own built from them:

| Component | Source | Notes |
|---|---|---|
| `Button` | shadcn | its variants (`default`, `secondary`, `outline`, `ghost`, `destructive`, `link`) and sizes; we add at least 44 px height on touch screens (`pointer: coarse`) |
| `Input`, `Label` | shadcn | the password form and login |
| `Card` | shadcn | panels, the map's empty message, profile sections |
| `Sheet` | shadcn (Radix Dialog) | modal: the full-screen photo detail on phones (§6) |
| `DropdownMenu` | shadcn | the account menu |
| `Avatar` | shadcn | initial of the email; the account menu trigger |
| `ToggleGroup` | shadcn | the System / Light / Dark choice |
| `Alert` | shadcn | inline errors and confirmations (replaces the red/green paragraphs) |
| `Tooltip` | shadcn | tab names on the icon rail |
| `SidePanel` | ours | the non-modal panel beside the grid or map on wide screens (§6), styled like a `Card`; Radix's Dialog is modal-first, so this is a plain `<aside>` with a close button and Escape |
| `EmptyState` | ours | icon, title, one or two sentences, optional `Button` action |

shadcn's `Sidebar` block was considered for §5 and left out: it brings its own mobile sheet and collapse state,
while we want a bottom tab bar on phones. The sidebar is our own layout using the `sidebar-*` tokens.

The existing pages switch to these components as they're restyled, and the inline `emerald-*`/`stone-*` classes
go away.

## 5. Adaptive layout and navigation

**Breakpoints (D2).** CSS decides the layout wherever it can. Both navigations are in the DOM, and the one not in
use is `display: none`, which also hides it from screen readers. JavaScript checks the screen size only where
behaviour differs, i.e. the photo detail's panel or sheet.

- **Narrow, below 768 px (`md`):** a top app bar with the page title and the avatar (→ profile), and a **bottom tab
  bar** with the five tabs (icon + label, at least 56 px plus `env(safe-area-inset-bottom)`). Single column.
  Pages use `100dvh`, so mobile browser bars don't cover the tab bar. `viewport-fit=cover` goes in the viewport
  meta tag.
- **Wide, 768 px and up:** a **left sidebar** with the logo, the five tabs and, at the bottom, the account menu
  (avatar + email → *Profile*, *Log out*). From 768 to 1279 px it's an icon rail (icons with small labels below).
  From 1280 px it's 240 px with labels beside the icons.

**Tabs and routes:**

| Tab | Route | Part 1 content |
|---|---|---|
| Catalogue | `/catalogue` | current grid and upload button, restyled |
| Species | `/species` | placeholder: "Every species you photograph gets a page with its photos and its English, Portuguese and scientific names. Coming in Phase 2." |
| Upload | `/upload` | placeholder (D8): "Drag and drop, the phone's photo picker, progress per file and species picked while uploading are coming here. For now, upload from the Catalogue." with a button to it |
| Map | `/map` | current map, restyled (§7) |
| Near me | `/near-me` | placeholder: "Species likely around you or a place you search, marked as photographed or not yet. Coming in Phase 2." |
| Profile | `/profile` | from the account menu (§5.1), not a tab |

`/` redirects to `/catalogue`, and `/account` to `/profile`, so old bookmarks and the session-expiry `next`
links still work. Login's `next` check (same-site paths only) is unchanged.

### 5.1 Profile page

From top to bottom: avatar and email; an empty slot where Phase 3's stats will go (no placeholder text, it's not
a tab); *Appearance* (System / Light / Dark); *Password* (the current `Account` form, moved, same behaviour and
messages); *Session* (when it ends, from `expires_at`, and *Log out*). Deleting the account (`DELETE /auth/me`)
stays out (§12).

### 5.2 Login

The same form and behaviour (expired notice, `next`) in the new style: logo, centred card, theme-aware.

## 6. Photo detail

One `PhotoDetail` component, used by the Catalogue and the Map, inside a `SidePanel` or a `Sheet`:

- **Wide:** a non-modal side panel, 420 px, on the right **beside** the grid or the map, which stays usable.
  Picking another photo replaces what the panel shows. The grid gets narrower and the map is resized
  (`invalidateSize` from a `ResizeObserver`).
- **Narrow:** shadcn's `Sheet` made full-screen, sliding up, with a back arrow. Radix traps focus, hides the rest
  from screen readers and returns focus to the opener on close.
- **State in the URL (D7):** `?photo=<id>` on `/catalogue` and `/map`. The browser or Android back button closes
  it, a link opens a photo directly, and reloading keeps it open. The Map's group panel uses the same panel/sheet
  pair, with its state kept in the component: groups depend on the zoom, so a `?group=` link would mean nothing.
- Contents as today (preview, date and offset, camera, lens, ISO, position text, the pick-on-map map with *Use
  this spot* / *Remove my position*), rearranged per the mockup. Species come in Part 2.

`useMediaQuery("(min-width: 768px)")` picks the mode. Tests stub `matchMedia` in `src/test/setup.ts` and cover
both.

## 7. Map tab

## 9. Decisions (confirmed 2026-11-16)

D6 and D8 were decided differently from the first draft. The others follow the recommendation.

| # | Question | Decision |
|---|---|---|
| D1 | Mockup format | HTML pages using the real tokens, served by Vite, rendered to WebP with the Playwright Docker image. No Figma/Penpot, so nothing has to be kept in sync by hand. |
| D2 | Breakpoints and navigation | Two layouts, switching at 768 px: bottom tab bar below it, left sidebar above it (icon rail up to 1279 px, labels from 1280 px). |
| D3 | Theme choice | System by default, with a Light/Dark override on the profile page, stored per device (`localStorage`), not per account. |
| D4 | Typeface | Inter variable, self-hosted. The alternative is the system font stack: no download, but a different look on every OS. |
| D5 | Icons | `lucide-react`. |
| D6 | Component library | **shadcn/ui** (Radix underneath), copied into `src/components/ui/` and owned by us (§4). The first draft proposed our own components on native elements. |
| D7 | Photo detail state | In the URL (`?photo=<id>`), so back closes it on phones. |
| D8 | Upload during Part 1 | **The upload button stays in the Catalogue** (restyled, same behaviour) and moves to the Upload tab in Part 2. Until then the Upload tab is a placeholder pointing to it. The first draft proposed moving it in Part 1. |
| D9 | Map tiles in dark theme | Leave the OSM tiles unchanged and theme only the controls and panels. Inverting the tiles (a common trick) makes water and forest the wrong colours, which matters on a birding map. |
| D10 | Roadmap: the catalog filters tick | Change the Phase 1 line in this plan's first PR to "filters by species, date and camera in the API; the UI filters arrive with Phase 1.5 → Catalogue tab", and put the filter bar plus paging in Part 2's Catalogue item. |

## 10. Pre-implementation checks

1. **shadcn CLI with this toolchain:** `shadcn init` and `add` work with Vite 8, Tailwind 4.3 and TypeScript 7
   (the CLI reads `tsconfig.json` for the `@/` alias; TS 7 has no JS API, see plan 0004 §1). If the CLI fails,
   components are copied by hand from the shadcn registry, which is what the CLI does anyway.
2. **Generated code vs. our checks:** the added components pass `oxlint --type-aware --deny-warnings` and
   `tsc` under our `tsconfig` (strict). Fix findings in our copy; disable a rule only for `src/components/ui/`
   and only if fixing it would mean rewriting the component.
3. **Radix in jsdom:** Sheet, DropdownMenu and Tooltip open and close in Vitest. Radix needs `ResizeObserver`,
   `hasPointerCapture`/`releasePointerCapture` and `scrollIntoView`, which jsdom lacks, so stubs go in
   `src/test/setup.ts`. Also check that DropdownMenu opens with `user-event` (Radix listens to pointer events).
4. **Bundle size:** compare `vite build` output before and after (Radix, `tailwind-merge`, Inter, lucide). A
   rough figure goes in the implementation notes.
5. **Playwright image:** `scripts/mockups.sh` renders `/design/*.html` from the Vite dev server inside the
   Playwright container (`--network host` on Linux), with Inter loaded before the screenshot (`document.fonts.ready`).
6. **Leaflet resize:** a map inside a container that narrows when the side panel opens redraws correctly after
   `invalidateSize`, with no grey tiles.

## 13. Implementation notes (step 1: shadcn, colours, mockups)

- **Colours (changed 2026-11-16):** the user asked to keep the app's existing colours for now and choose new
  ones later, independently of the logo. The shadcn variables carry the pre-1.5 palette: emerald-700 for
  `primary` (emerald-400 in dark), stone for surfaces and text, emerald-100 for `accent` (the old nav hover),
  amber-700 for `warning`. A first kingfisher-blue palette was dropped.
- **shadcn:** `shadcn init -t vite -b radix -p nova` works with Vite 8, Tailwind 4.3 and TypeScript 7
  (check 1 passed). It also adds `cn` (shadcn's own clsx + tailwind-merge replacement, MIT, no install
  scripts) and the Geist font, which was swapped for `@fontsource-variable/inter` (D4). `shadcn` moved to
  `devDependencies`, since only the build reads its CSS. The `@/` alias is in `tsconfig.json` and `vite.config.ts`.
- **Components deferred to step 2:** all nine from §4 were added and pass `tsc` and oxlint after one fix
  (`toggle-group.tsx`'s `as React.CSSProperties`, which becomes unnecessary with a `CSSProperties`
  augmentation for `--*` properties; check 2 passed). Unused and untested, they broke the 100% coverage
  gate, so they were removed again and come back with their tests in step 2 (`npx shadcn add card input
  label sheet dropdown-menu avatar toggle-group alert tooltip`, then reapply the `toggle-group` fix).
- **Logo:** `frontend/public/logo.svg`, a flat common kingfisher perched sideways on a branch, facing right,
  in its own fixed colours. A second draft leaned the body forward so it fills the square and still reads at
  16 px. `docs/design/logo.webp` shows it at several sizes and on light and dark.
- **Mockups:** `frontend/design/*.html` with a shared `shell.js` (navigation, lucide icons taken from
  `lucide-react`'s icon data, sample species in three languages, placeholder photos as CSS gradients, OSM
  tiles placed as Leaflet would) and `mockup.css` (the app's CSS plus `@source` for `design/`, so the app's
  bundle doesn't change). The Catalogue and Upload mockups show the **Part 2** versions (filter bar, no
  upload button; drop zone, per-file progress, species picker), since the designs are agreed before either
  part builds them.
- **Rendering:** `scripts/mockups.sh` runs Vite and Chromium together inside
  `mcr.microsoft.com/playwright:v1.65.1-noble` (check 5 passed), so it needs no host networking; Docker
  Desktop has to be running. Playwright's host Chromium does not start in this WSL (missing `libnspr4` and
  others), which is why the container is the only path. shellcheck is clean (run with the
  `koalaman/shellcheck` image, since it isn't installed on the host).
- **Build:** the app's CSS is 52.8 kB (14.0 kB gzip) with Inter and shadcn's base styles; Inter ships all its
  subsets, but `unicode-range` means browsers fetch only Latin (48 kB) and Latin-Ext when needed.
- **Not shown in the mockups:** the 768–1279 px icon rail (the screenshots are 1440 and 390 wide).

## 14. Implementation notes (step 2: foundation)

- **Components:** `npx shadcn add button card input label sheet dropdown-menu avatar toggle-group alert tooltip
  badge` (Badge added to the plan's list: the mockups use it for the "Coming in Phase 2" pill). This shadcn
  version imports `cn` directly from the `cn` package, so there is no `src/lib/utils.ts`. Changed in our copies
  to match the mockups:
  - `Button`: `rounded-md`; default size `h-9 px-4 gap-2`, `icon` `size-9`, `lg` `h-11 px-6`; `shadow-xs` on
    `default` and `outline`; on touch screens (`pointer-coarse:`) default buttons are `h-11` and icon buttons
    `size-11`, the 44 px touch target from §4.
  - `Input`: `h-9 rounded-md px-3 shadow-xs`, `h-11` on touch screens.
  - `Card`: a `border` with `shadow-sm` instead of Nova's `ring-1`; `CardTitle` semibold.
  - `AvatarFallback`: the emerald initial (`bg-primary text-primary-foreground font-semibold`).
  - `ToggleGroup`: no `as React.CSSProperties`; `src/react-css.d.ts` types `--*` properties in `style`.
- **Ours:** `ThemePicker` (the profile mockup's segmented System / Light / Dark, on `ToggleGroup`; clicking the
  chosen option keeps it rather than letting Radix deselect it), `SidePanel` (non-modal `<aside>` with title,
  actions, Close and Escape, which can be handed to a nested panel with `closeOnEscape={false}`), `EmptyState`
  (icon, title, text, optional action and note).
- **Theme:** `public/theme.js` loads blocking in `<head>` and sets `.dark` before the first paint; `src/theme.ts`
  (`storedTheme`, `setTheme`, `applyTheme`, `followSystemTheme`) takes over, and `main.tsx` follows system
  changes. Both treat blocked storage as "system". Choosing System removes the stored value.
- **Favicon:** `logo.svg` as the icon, and `public/apple-touch-icon.png` (180 px, logo on stone-50 with
  padding, since iOS fills transparency with black), rendered once in the Playwright container.
- **Tests:** 141 (35 new), 100% lines, branches, functions and statements, three runs in a row with no failures
  and no `act()` warnings. `src/components/ui/ui.test.tsx` reaches every exported part and variant, including
  ones no page uses yet (dropdown checkbox/radio/sub items, avatar groups), so the copies stay as upstream
  ships them. Check 3: jsdom lacks `ResizeObserver`, pointer capture, `scrollIntoView` and `matchMedia`;
  `src/test/setup.ts` adds stand-ins only where missing, and `src/test/media.ts` has a controllable
  `matchMedia`. In this shadcn version `Tooltip` requires a `TooltipProvider` (step 3 wraps the app in one).
- **Check against the mockups:** `frontend/design/components.tsx` renders the real components;
  `docs/design/components.webp` and `components-dark.webp` show them next to nothing else, for comparison.
- **Size (check 4):** app CSS 89.3 kB (19.6 kB gzip), up from 52.8 kB, since the components' classes are now
  in the build; JS unchanged at 492.5 kB (153 kB gzip), because no page imports the components yet. Step 3
  measures again once they're used.

## 16. Implementation notes (step 4: photo detail, Catalogue, Map)

- **Dark-mode bug (reported 2026-11-16):** the photo detail, the map's group panel and the Catalogue grid still
  hard-coded `bg-white`, `stone-*` and `emerald-*`, so in the dark theme they stayed light. Every such class in
  `src/` is now a theme token. The only fixed colours left are the photo detail's two map markers (emerald-700
  saved, amber-700 picked) and the markers' white ring, which sit on the always-light OSM tiles (D9).
- **`ResponsivePanel`:** `SidePanel` from 768 px (`useMediaQuery(WIDE)`), otherwise shadcn's `Sheet` made
  full-screen (`side="bottom"`, `top-0`, `h-dvh`) with a back arrow and the title as `SheetTitle`; the slide-in
  is off under `prefers-reduced-motion`. `PhotoDetail` and `GroupPanel` are now only content; closing, Escape
  and the title belong to the panel.
- **`?photo=` (D7), `usePhotoParam`:** opening pushes an entry (marked in history state), switching photos
  replaces it, closing steps back when this page opened it and otherwise drops the parameter (a link or a
  reload), so neither Back nor Close leaves the page. A non-numeric value is ignored; an id that can't be
  loaded is dropped from the URL. The Catalogue fetches a linked photo that isn't on the loaded page.
- **Map:** one panel at a time. A photo opened from a group takes the group's place, and closing it brings the
  group back (Escape twice closes both, as before). Group titles read "12 photos here", with *Zoom in* in the
  title bar. The map container is `isolate`d, so Leaflet's controls (z-index 1000) can't cover the phone sheet.
  `InvalidateOnResize` (a `ResizeObserver` on the map container) redraws Leaflet when a side panel opens
  beside it or a sheet animates in. Group markers use `primary`/`primary-foreground`. Leaflet's zoom buttons
  and attribution use theme colours (`index.css`); the empty-map message is a `Card`.
- **Photo detail:** the mockup's layout: preview, *Details* (Taken with offset and "set by you", Camera, Lens,
  Settings as ISO · f/ · shutter · focal length, File as format, dimensions and size), *Where* (position text,

  come in Part 2.
- **Catalogue:** heading on wide screens, the upload button (now a real `Button` opening a hidden file input; the
